# Purpose

This document defines the information security requirements and controls for managing risks associated with outsourced development at Agile Labs Pte Ltd. The objective is to protect the company’s intellectual property, customer data, and information assets from security threats when engaging with external vendors.

# Scope

This policy applies to all software development, web development, mobile app development, and UI design projects outsourced to third-party vendors, contractors, or consultants.

# Policy Statement

1. Vendor Selection and Contracting
    - Due Diligence: Conduct thorough due diligence on potential vendors to assess their information security practices and compliance with international standards such as ISO/IEC 27001.
    - Contractual Obligations: Include detailed security clauses in contracts, specifying requirements for data encryption, secure code practices, vulnerability management, and incident reporting. Contracts must also include penalties for security breaches and non-compliance.
2. Data Protection and Confidentiality
    - Data Handling Protocols: Implement strict data handling protocols that vendors must follow, including data encryption during transit and at rest, use of secure file transfer methods, and detailed logging of data access and transfers.
    - Confidentiality Agreements: Require all vendor staff involved in the project to sign non-disclosure agreements to safeguard sensitive information.
3. Access Control
    - Authentication and Authorization: Ensure that access to Agile Labs Pte Ltd’s systems by vendor personnel is controlled through multi-factor authentication and strong password policies.
    - Regular Audits: Conduct regular audits of vendor access logs and security practices to ensure compliance with access control policies.
4. Security Practices and Compliance
    - Secure Development Lifecycle: Vendors must adhere to a secure development lifecycle that includes security reviews at each stage of development.
    - Patch Management: Implement a robust patch management policy to ensure that all third-party software used in the development process is up-to-date with the latest security patches.
5. Incident Management
    - Immediate Reporting: Vendors must report any security incidents involving Agile Labs Pte Ltd’s data or systems within 24 hours of discovery.
    - Incident Response Plan: Vendors should have a well-documented incident response plan that aligns with Agile Labs Pte Ltd’s incident management procedures.
6. Training and Awareness
    - Security Training: Ensure that all vendor personnel receive regular training on the latest security threats and best practices. Training should include specific sessions on secure coding practices and data protection laws relevant to the project.
    - Security Awareness Campaigns: Conduct joint security awareness campaigns with vendors to foster a culture of security.

# Enforcement

- Audit Rights: Agile Labs Pte Ltd reserves the right to audit vendors for compliance with this policy. Audits may include onsite visits, remote checks, and review of security documentation.
- Non-compliance: Non-compliance with this policy can lead to remedial actions, financial penalties, or termination of the contract, depending on the severity of the issue.

# Review and Update
- Annual Reviews: This policy will be reviewed annually or after any significant incident to ensure it remains relevant and effective.
- Continuous Improvement: Encourage continuous feedback from project teams and vendors to improve security practices and policy effectiveness.
